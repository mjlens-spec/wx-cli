# 微信工作助手

这是独立于 Dashboard 的本机微信读取工具。它为 Codex 和 Claude 提供消息、图片和有出处的分析材料，由当前 AI 会话提炼成待办、客户回复草稿、项目风险和工作建议。

## 使用

在新的 Codex 或 Claude Code 会话里直接说明需求，例如：

- “读取最近三天某项目相关微信，整理仍未完成的事项，列出负责人和出处。”
- “看一下项目群里今天发的图片，结合客户反馈给出修改建议。”
- “根据最近的项目聊天，建议我今天优先处理哪三件事。”

Codex 可显式调用 `$wechat-work`。Claude Code 可用 `/wechat-work`。新安装的 Skill 如未立即出现，在新会话中调用。

## 功能和边界

| 能力 | 行为 |
|---|---|
| 会话与消息 | 指定会话和日期读取，保留消息出处、时间和分页状态 |
| 图片 | 精确匹配消息，优先读取高清缓存，标明缩略图或未缓存情况 |
| 工作材料 | 多会话整理成私有临时材料；AI 基于原文和实际查看过的图片分析 |
| 隐私 | 复用本机密钥，过滤底层 XML 和常见访问字段，不调用额外模型服务 |
| 清理 | 只清理本工具生成的临时任务目录 |

工具不主动发消息、不自动修改业务文档、不创建后台任务。读取动作不依赖 Dashboard 页面或服务。

默认最近 3 个本地自然日。消息每批每会话最多 200 条、材料准备最多 12 个会话；按分页继续读取即可扩大范围。图片每批最多 8 张、单张最大 12 MB。尚未提供语音转写或视频理解；看到消息类型不等于理解了内容。

## 安装与调用

支持 macOS、Python 3.9 及以上和原生 Rust `wx-cli` 0.7.4 及以上。源码只使用 Python 标准库；需要先完成原生读取器的配置，确保账号数据和有效密钥可用。安装器把运行文件放到稳定目录，给两种 AI 安装同一份 Skill；更新已管理文件前会备份。

```sh
python3 tools/wechat-work/install.py --account-dir '/path/to/xwechat_files/account'
~/.local/bin/wechat-work status
~/.local/bin/wechat-work sessions --limit 100
~/.local/bin/wechat-work history --chat '会话名称或 ID' --since 2026-09-24 --until 2026-09-26
```

首次安装必须明确指定账号目录，该目录直接包含 `db_storage`。可用 `--binary /path/to/wx-cli` 指定程序；可用 `--agent codex` 或 `--agent claude` 只安装一个入口。再次运行安装器会保留既有账号绑定，显式传入参数可更新配置。旧 Claude `/wx-image` 仅在传入 `--replace-wx-image` 时备份并替换。

运行目录：`~/.local/share/wechat-work/`。
命令入口：`~/.local/bin/wechat-work`。
底层程序：`~/.local/bin/wx-cli`。
密钥继续由原生 wx-cli 管理，安装不迁移、不复制、不提取密钥。

配置固定绑定安装时的微信账号；微信切换账号后需要明确更新绑定并验证，避免静默读取其他账号。旧 `wx` 和 Dashboard 保留原有配置，本工具不调用它们。

图片内容和消息属于私有数据。`prepare` 的临时文件为 0600、目录为 0700，完成分析后用 `cleanup --job` 清理。直接用 `image` 保存的文件由调用者管理，不自动删除。过滤字段不保证去除用户聊天文本中的全部敏感信息；材料进入当前 AI 会话后，遵循该宿主的隐私设置。

## 验证

在仓库根目录运行 `python3 -m unittest discover -s tools/wechat-work/tests -v`。测试使用合成数据，覆盖消息与图片精确关联、账号校验、字段过滤、分页、图片回退、临时目录清理、安装备份、输出拒绝覆盖及 macOS `/tmp` 路径兼容。真实微信记录、配置和缓存不应提交到仓库。
